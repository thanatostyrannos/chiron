**status** is updated; rows are never deleted. Every assumption baked into the

## Open blockers derived from the above

- **`hardware-capacity-ceiling` is still not exactly measured.** What is established
  `[M]` is a floor: **≥74.40 GiB written, read back and released**. The "82.67 GiB"
  figure this bullet previously reported as the answer was a probe returning its own
  search bound, and stating it as measured contradicted the row above it. Corrected
  2026-07-26. Not on the critical path — `gpu-fast-tier-size` is the binding number.
- ~~**The number that actually binds is smaller than the ceiling.**~~ Resolved
  2026-07-26 by `notebook/uma-carveout-controls-fast-tier.md`: BIOS UMA FB Size set to
  96 GB, fast tier moved from 30 GiB to **≥62 GiB** at ~200 GB/s. Budget long-context
  experiments against 62 GiB.
- **Single tensors ≥32 GiB hang or fault** (`large-tensor-fault-32gib`). Keep individual
  buffers under 32 GiB until the Hardware Validation Gate characterises it. The hang
  presents at 0 CPU with no error, so a long run would stall rather than fail.
- **Numerics remain unproven** (`bf16-numerics-unproven`). The Hardware Validation Gate
  has not run. No result from this machine counts as evidence yet.
